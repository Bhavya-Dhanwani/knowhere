# Project Review Service

Evidence-grounded project evaluation and cohort ranking for Knowhere LMS.

## Evaluation flow

1. The authenticated API validates a canonical GitHub URL and queues an evaluation in BullMQ.
2. A worker clones without hooks or submodules, resolves the requested ref to an immutable commit SHA, and checks out that commit detached.
3. Recursive discovery records every visited file, its classification, byte size, and SHA-256 when analyzed. Generated, binary, oversized, unreadable, and ignored content is explicit in the manifest.
4. Semgrep, Gitleaks, and Trivy run through the isolated static-analysis endpoint. Local trusted-tool execution is disabled by default and exists only as an explicit development escape hatch; it still uses argument arrays, timeouts, capped logs, exit status, and output hashes.
5. Participant build/test/runtime, browser, and API checks are sent only to authenticated isolated-runner endpoints. If a runner is not configured, the evidence says `UNAVAILABLE`; the service does not substitute sample metrics.
6. Deterministic scoring uses successful objective evidence. LangChain/Mistral can score only qualitative criteria from the bounded evidence packet. Missing criteria have zero confidence and do not silently become baseline scores.
7. Ranking uses confidence-weighted rubric comparisons. Cohorts over 100 use a connected sparse tournament, avoiding quadratic all-pairs growth. Exact statistical ties receive shared ranks.
8. JSON, CSV, and Markdown reports include commit provenance, evidence coverage, confidence, and actionable evidence gaps.

## Local setup

Copy `.env.example`, start MongoDB and Redis, and run:

```sh
pnpm --filter project-review-service dev
```

The service refuses to enqueue evaluations if `REDIS_URL` is absent. Runtime-dependent criteria remain partial until the corresponding isolated runner is configured.

## Isolated runner contract

Each runner is an internal authenticated HTTP endpoint accepting a pinned repository or target descriptor and returning structured JSON. Deploy participant-code runners as Kubernetes Jobs generated by `KubernetesSandboxManifestGenerator`: gVisor runtime class, non-root UID, read-only root filesystem, no service-account token, dropped Linux capabilities, bounded CPU/memory/storage/time, and deny-by-default networking.

Never expose runner endpoints publicly. Pin runner images by digest and allow egress only to explicitly required targets and artifact storage. Runner output artifacts should be uploaded to S3-compatible immutable storage and returned as object references; the API stores those references in evidence.

## API exports

- `GET /api/review/submissions/:id/report` — full JSON evidence report
- `GET /api/review/submissions/:id/report.csv` — criterion-level CSV
- `GET /api/review/submissions/:id/report.md` — human-readable Markdown review
- `GET /api/review/submissions/:id/replay` — activity replay trace

All review routes require a bearer token. Event mutation, evaluation dispatch, ranking, deletion, and overrides have role checks. Judge overrides require a reason and create an append-only audit record.
