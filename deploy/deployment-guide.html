Deploying Knowhere

Media lives in one AWS storage account for the long run. The app runs in a second account on AWS, Google Cloud or Azure. You finish all the browser work in one account, sign out, do the other, then do the rest from your PC. Every user gets only the access it needs.

1The two accounts

Storage account (AWS) cents / month

  • Two private, encrypted S3 buckets: raw uploads and transcoded videos
  • Set up once. It stays the same whichever cloud runs the app
  • Kept when you tear the app down, so your content survives

App account

  • EKS Lean: EKS with one t4g.medium spot node, about $89/month (≈34 days on $100)
  • Reaches the buckets through an IAM role: no storage keys at all
  • GKE, sized by the plan you pick (GKE Spot ≈ $105/month)
  • Reaches the buckets with a key that can only touch those two buckets
  • AKS, sized by the plan you pick (AKS Spot ≈ $101/month)
  • Reaches the buckets with a key that can only touch those two buckets
Storage account in the browser→sign out→App account in the browser→sign out→Your PC: CLI, secrets, Deploy
The deploy creates all infrastructure: buckets, cluster, registry, secrets store, roles. Don't create any of it in a console: the names are fixed, and an existing one makes the deploy fail. In the browser you only create users, policies, keys and budgets.
AWS "Free plan" accounts (the account menu shows credits and days remaining) are closed when the free period ends or the credits run out, unless upgraded to the paid plan. Upgrade the storage account before that date, or the buckets and your media go with it. New accounts can show "verification in progress" for up to 2 days; deploys fail until it finishes, but the IAM work in parts 4 and 5 already works.

2Choose the app cloud

The guide follows your choice. Account IDs are typed in later, in each account's own part. Everything you type is saved only in this browser.

3Before you start

  1. Docker Desktop is running. Images are built on this machine; close heavy apps during the build.
  2. Node 22 + pnpm, and pnpm install has been run in the repo.
  3. AWS CLI v2 (aws --version). The storage account always needs it.
  4. Google Cloud CLI (gcloud version) with gcloud components install gke-gcloud-auth-plugin, plus skaffold and kubectl.
  5. Azure CLI (az version), plus skaffold and kubectl.
  6. MongoDB Atlas ready (production connection strings go in k8s/secrets.yml).
  7. Optional: a domain. It's needed for voice/video, because browsers only allow the camera and microphone over HTTPS.
  8. MFA on every root / owner login. Never deploy with those logins.

App on AWS: nothing to do here. The first deploy (part 9) sets up the storage account (S3-only) and creates the buckets itself.

Run this once, from the repo. The buckets then stay for as long as the storage account exists.

8Prepare your secrets

k8s/secrets.yml holds every app secret. It's gitignored and never enters images or the CDK output. Check it has your production values:

  • MongoDB Atlas connection strings (not the *_dev databases)
  • JWT / refresh-token and service-token secrets: long random values. Production refuses placeholders.
  • Mistral API keys and mail (SMTP) settings

Leave the storage keys in media-secrets empty. On AWS the stack fills in the bucket names, Redis URL and LiveKit keys, and the services reach S3 through an IAM role.

Point media-secrets at the storage account with the key from app-storage.csv:

k8s/secrets.yml: the media-secrets part
apiVersion: v1
kind: Secret
metadata:
  name: media-secrets
type: Opaque
stringData:
  AWS_REGION: '{{REGION}}'
  AWS_ACCESS_KEY_ID: '<from app-storage.csv>'
  AWS_SECRET_ACCESS_KEY: '<from app-storage.csv>'
  S3_RAW_BUCKET: 'knowhere-raw-{{B}}-{{REGION}}'
  S3_TRANSCODED_BUCKET: 'knowhere-transcoded-{{B}}-{{REGION}}'
  CLOUDFRONT_DOMAIN: ''

12Where your secrets live, and are they safe?

Yes, for this setup. Nothing is in git or the images. In the cloud they are encrypted, and only the app and you can read them. Your PC holds the plaintext originals, so that's the part to protect.

WhereWhatProtection
Your PC: k8s/secrets.yml, packages/*/.env, .dev-keys.jsonPlaintext originalsGitignored (none tracked, none in history), excluded from images and CDK output. Keep BitLocker on.
Your PC: %USERPROFILE%\.aws\credentials, C:\keys\knowhere-deployer.json, the az login cacheDeploy credentialsReadable only by your Windows user. Each identity has least access. Rotate keys every few months.
Deploy manager: deploy/.state/History, logsNo secret values in logs. The temporary secrets.yml copy is deleted after each job. The UI is localhost-only, behind a token.
App account: Secrets Manager knowhere/*App secretsKMS-encrypted. Readable only by the External Secrets role and admins.
Inside the clusterSecrets the pods readEncrypted at rest by EKSGKEAKS. Cluster admins only.
Storage accountNothingThe app uses an IAM role: no storage keys exist.
Storage key (knowhere-app-storage)In secrets.yml and the clusterReaches only the two Knowhere buckets. To rotate: new key → update secrets.yml → Deploy → delete the old key.
